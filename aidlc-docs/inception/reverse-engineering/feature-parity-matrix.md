# Feature Parity Matrix — bim-crm ↔ mobile app

Generated by AI-DLC Reverse Engineering — 2026-08-05.

The user's requirement is **"all features in the mobile app."** This matrix is the definition of
"all": every bim-crm capability, its current mobile status, and what it needs.

Sources: `bim-crm/FEATURE_LOG.md`, `bim-crm/routes/web.php` (90+ routes, 27 controllers),
`src/components/*` on `cms-integration` (27 components), `src/lib/cockpit.ts` (31 functions).

**Status legend**
`✅ mobile` — exists on `cms-integration` today (Cockpit-backed; needs re-pointing, not rebuilding)
`🔶 partial` — a related screen exists but the CRM capability is richer
`❌ absent` — no mobile equivalent; net-new screen
`🚫 web-only` — deliberately excluded from mobile (see rationale)

**"All features" is ~40 mobile surfaces against ~35 API endpoints.** Correction to a stated premise:
`cms-integration` has **better UI and better tooling** — a 497-line design system, react-query, axios,
Entra PKCE, secure storage, EAS release pipeline — but it has **no tests**. `git ls-tree` finds zero
test/spec files on any branch of this repo, and `package.json` has no test script. Test infrastructure
is net-new work, which is why Q8 asks about it rather than assuming a suite exists to extend.
