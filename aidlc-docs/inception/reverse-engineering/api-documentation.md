authenticated by **session cookie**. A React Native client cannot consume either.

### What the mobile app expects but does not get

Two conventions in this dead client are worth keeping, because they already match Laravel's defaults
and reduce the work: the error envelope `{message, errors: {field: [...]}}` is exactly Laravel's
validation response, and the paginated envelope `{data, meta}` with `per_page` is exactly
`JsonResource::collection` over a paginator. Adopting them is free.

## Part 2 — Proposed API surface

Design rules, in priority order:

1. **The API is a presentation layer.** Every endpoint routes through the existing policy and service
   objects. Authorization, quotation numbering, and total recalculation are never reimplemented.
2. **`auth:sanctum` on everything** except the two auth entry points and the existing public
   quotation routes.
3. **Row-level scopes are not optional.** Every index applies `visibleTo`/`forUser`. An endpoint that
   returns unscoped rows is a defect.
4. **`/api/v1/` prefix**, matching what the client already calls.
5. **API Resources for every response.** No `->toJson()` on a model — that leaks columns.

## Part 3 — Exposure and operational concerns

| Concern | Requirement |
| --- | --- |
| **CORS** | Required — Expo Web is a browser origin. `api.ts:extractNetworkErrorMessage` already warns about this exact failure, so it has been hit before. Allowlist the Expo dev origin and any web build host; do not use `*` with credentials. |
| **Rate limiting** | Add an `api` throttle group. `trustProxies` is already correct, so per-IP buckets will use the real client IP rather than Traefik's. |
| **Token lifetime** | Sanctum tokens do not expire by default. Set an expiry and support refresh, or a lost phone is a permanent credential. |
| **Token storage** | `expo-secure-store` (Keychain / Keystore) — already a dependency. Never AsyncStorage for tokens. |
| **Versioning** | `/v1/` from day one. |
| **`@bimgoc.com` hardcode** | **Blocks every mobile login.** `MicrosoftController` refuses non-`@bimgoc.com`; mobile users are `@bimats.com`. Must become configurable — this is CRM gap #2 and it is now on the critical path. |
| **Contract documentation** | Generate an OpenAPI spec so the client's types can be derived rather than hand-mirrored. |
| **Superadmin `Gate::before`** | CRM gap #4: superadmin holds power only via seeded permissions. A new API permission added without re-seeding would silently exclude superadmin. Worth fixing while adding ~48 endpoints' worth of permissions. |
